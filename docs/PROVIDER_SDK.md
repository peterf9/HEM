# HEM Provider SDK Specification

> Version 1.0

This document defines how to build, test, and integrate custom Providers and Capabilities for the **HomeLab Enterprise Monitor (HEM)** framework.

---

# Overview

A **Provider** in HEM bridges Asset capability requirements with Home Assistant entity generation.

Providers are completely decoupled from the Core compiler and communicate strictly via Contracts and Capabilities.

---

# Architecture & Hierarchy

```
Asset (Declares Capabilities required)
  │
  ▼
Provider (Registers Capabilities supported)
  │
  ▼
Capabilities (Availability, Latency, Jitter, PacketLoss, etc.)
  │
  ▼
Jinja2 Template Generation ──> Home Assistant Entities
```

---

# 1. Defining Capabilities

Capabilities declare monitoring features supported by a Provider.

```python
from enum import Enum

class Capability(str, Enum):
    AVAILABILITY = "availability"
    LATENCY = "latency"
    JITTER = "jitter"
    PACKET_LOSS = "packet_loss"
    METRICS = "metrics"
```

---

# 2. Creating a Custom Provider

Every Provider inherits from `BaseProvider` and registers its supported capabilities.

```python
from typing import List, Set
from hem.providers.base import BaseProvider
from hem.providers.capabilities import Capability

class PingProvider(BaseProvider):
    name: str = "ping"
    capabilities: Set[Capability] = {
        Capability.AVAILABILITY,
        Capability.LATENCY,
        Capability.JITTER,
        Capability.PACKET_LOSS,
    }

    def template_name(self) -> str:
        return "providers/ping.j2"
```

---

# 3. Provider Registration

Providers register themselves with the central `ProviderRegistry`:

```python
from hem.providers.registry import ProviderRegistry
from hem.providers.ping import PingProvider

registry = ProviderRegistry()
registry.register(PingProvider())
```

---

# 4. Testing a Provider

Every custom Provider must include unit tests verifying:
1. Registration & Capability discovery.
2. Template rendering against an Asset loaded via `AssetLoader`.
3. Validation of generated `unique_id` and entity names.

---

# Provider Naming Conventions

- Provider IDs must be lowercase slug strings (e.g., `ping`, `snmp`, `mqtt`, `rest`).
- Entity unique IDs generated by a provider must use the prefix: `hem_<asset_id>_<capability>`.
